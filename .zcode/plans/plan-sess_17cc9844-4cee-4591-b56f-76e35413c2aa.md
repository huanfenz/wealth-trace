# wealth-trace 修复方案(用户名密码鉴权 · 90 天滑动会话)

分 5 个阶段,每阶段一个 commit,可独立验证回滚。鉴权采用**用户名密码登录 + Bearer 会话令牌,90 天滑动有效期**(每次 API 调用续期;只要 90 天内用过一次就无需重登,令牌存 localStorage、会话库存 SQLite 后端重启不掉线、多设备各自独立、改密码吊销全部会话);其余修复项与此前审阅方案一致。

## 阶段 1:用户名密码鉴权 + 移除通配 CORS(阻塞项)

### 后端

1. **密码学工具** 新增 `backend/src/utils/crypto.cpp` + `include/utils/crypto.hpp`:SHA-256、HMAC-SHA256、PBKDF2(200k 迭代,常量可调)、`random_bytes()`(读 /dev/urandom)、常量时间比较。**必须附 RFC 6234(SHA-256)/RFC 7914(PBKDF2)官方测试向量的单元测试**。不引入 OpenSSL(vendored 依赖结构下 arm64 交叉编译成本过高)。

2. **迁移 015** `migrations/015_auth.sql`:
   - `auth_user(id, username UNIQUE, password_hash, created_at, updated_at)` — 预留多用户,本期服务层只允许一个账号;
   - `auth_session(token_hash PK, user_id REFERENCES auth_user, created_at, expires_at, last_used_at)` — 只存令牌 SHA-256 哈希,导出/备份的 .db 泄露不会泄露可用会话。

3. **AuthService** `include/service/auth_service.hpp` + impl:
   - `status()` → {enabled(来自 config), initialized(有无账号)};
   - `setup(username, password)` 仅当无账号时可用(持全局锁,防并发双创建),密码 ≥8 位,PBKDF2 哈希入库,返回新会话;
   - `login(username, password)` 校验 PBKDF2,**失败按用户名做内存退避(1s/2s/4s…封顶 30s,防爆破)**,成功签发 32 字节随机令牌、库存哈希、**90 天滑动过期**(validate 时检查并续期);
   - `validate(token)` 供中间件调用:查哈希、查过期、滑动续期;`logout(token)` 删会话;`change_password(old, new)` 校验旧密码后更新哈希并**吊销该用户全部其他会话**。
   - 全方法遵守现有 `scoped_lock(database_.mutex())` 纪律。

4. **AuthController** 新增 `controller/auth_controller.cpp`:公开路由 `GET /api/auth/status`、`POST /api/auth/setup`、`POST /api/auth/login`;需登录路由 `POST /api/auth/logout`、`POST /api/auth/password`。

5. **AuthMiddleware** 新增 `include/controller/auth_middleware.hpp`(全局中间件,`using App = crow::App<AuthMiddleware>;`):
   - 放行:非 `/api/` 前缀(SPA 壳)、`/api/health`、`/api/auth/*` 三个公开端点、`auth.mode == "disabled"` 时全部放行;
   - 其余校验 `Authorization: Bearer <token>` → `AuthService::validate`;失败 401(新错误码 `kUnauthorized = 40101`,格式同 `http::fail`)。
   - 中间件经 `app.get_middleware<AuthMiddleware>().configure(...)` 注入 AuthService 引用;13 个控制器 `register_routes(crow::SimpleApp&)` 签名机械替换为 `register_routes(App&)`,业务代码不动。

6. **config**:`AuthConfig { std::string mode = "required"; bool allow_unauthenticated_lan = false; }`,解析 `auth.mode`/`auth.allow_unauthenticated_lan`。`main.cpp` 启动硬闸:`mode == disabled` 且绑定非 127.0.0.1/::1/localhost → 拒绝启动(除非 allow_unauthenticated_lan)。

7. **删除全部 3 处通配 CORS**:`http_util.hpp:23-25`、`main.cpp:143-151`(OPTIONS catch-all 整体删除)、`database_controller.cpp:200`。

### 前端

11. **登出入口**:`App.vue` 顶栏加当前用户名 + 登出按钮;"修改密码"入口放登录页。仓库根 `config.json` 增加 `"auth": {"mode": "disabled"}` 保持本地开发流不变。

## 明确不做(记录理由)

- 多用户/按家庭成员分权:表结构预留,本期单管理员;属产品级扩展。
- TLS/HTTPS:明文传输边界在 README 说明,建议 caddy/nginx 反代,超出本轮。
- 登录 IP 级限流/验证码:按用户名退避已覆盖家用场景。
- 转账可透支:疑似产品语义,待产品确认。
- `money.cpp/rate.cpp` 解析器位数上限:当前无 HTTP 调用路径,不动。
